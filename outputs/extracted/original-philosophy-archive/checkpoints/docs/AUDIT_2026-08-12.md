MCP server, and an editorial/MCP layer. The IPVV (Abhinavagupta's Vivṛtivimarśinī) is the flagship
work, now published as 49 lazy-JSON passages with C1 + themes + a deterministic verification floor.

## 3. The problems (the non-cohesion)

### 3.1 Uncommitted work — the single biggest risk
The entire Phase-0/2 build (the deterministic substrate: C1 wiring, themes, verify services, the
lazy store, canonical spines) plus the whole `machinelearning/` folder is **untracked**. If anything
happens, ~weeks of work is unprotected. **This is the top fix.**

### 3.2 `npm test` is not self-contained
`package.json` test = `python3 tests/api_suite.py`, an HTTP test needing `npm run dev`. The real
invariant tests (`ipvv_published.test.ts`) run via `npx tsx` and are not wired into `npm test`. A
fresh agent runs `npm test` → failure, and doesn't know why.

### 3.3 Disk bloat (not git-tracked, but messy)
- `machinelearning/research/.venv` — 5GB local virtualenv (torch/nvidia). Gitignored (OK) but should
  be documented/removed from a shared workspace.
- `data/corpus/units/_archive_generated` — 132MB of superseded generated units (the lazy store
  replaced them). Untracked; should be removed (the provenance is preserved elsewhere).

### 3.4 Docs sprawl — overlapping handovers
10 root-level `.md` + 5 `HANDOVER*.md` + `docs/` (37) + `docs-site/` + `machinelearning/` (16) —
several overlap (HANDOVER_FINAL vs HANDOVER vs HANDOVER_NEXT vs STATE_OF_PLAY vs PROCESS_NOTES).
A new agent can't tell which is current.

### 3.5 The data store is now the source of truth, but old paths linger
`data/corpus/published.ts` now lazy-loads from `data/published/ipvv/`; the 132MB `_archive_generated`
and the old `data/corpus/units/*-generated.ts` (Kramasadbhāva) coexist. The split between "lazy
store" and "bundled units" isn't documented as a policy.

## 4. The organization plan (in order)

### Step 1 — Commit the work (top priority)
- Review `git status`, stage the intended changes, write a clear commit (or sequence) covering the
  Phase-0/2 build + the lazy store + the docs.
- Verify nothing sensitive (the `.env` with R2 creds is gitignored) is committed.

### Step 2 — Fix the test command (make it self-contained + honest)
- Wire the invariant tests into `npm test`: `npm test` should run `npx tsx tests/ipvv_published.test.ts`
  (and any `*.test.ts`), and `npm run test:api` should run the server-dependent `api_suite.py` with
  a documented prerequisite.
- Update `package.json` + add a `tests/README.md` explaining both.

### Step 3 — Clean disk + document policy
- Remove `data/corpus/units/_archive_generated/` (132MB superseded; provenance is in the lazy store
  + git history). Keep the hand-authored `1.5.11-published.ts` and Kramasadbhāva units.
- Add a `.gitignore` entry + a note that `machinelearning/research/.venv` is a local ML environment,
  not part of the app (already gitignored; document it).

### Step 4 — Consolidate the docs (single source of truth)
- Create a `docs/INDEX.md` that names the ONE current handover per concern:
  - **System**: `THE_COMPANION.md` (sanskritree specs) + `docs/PHASE1_IPVV_CORPUS_PROCESS_NOTES.md`
  - **ML strategy**: `machinelearning/MLUSEINPATALA.md`
  - **Editorial/corpus**: `HANDOVER_FINAL.md` (or a renamed current one)
- Mark the stale/duplicate handovers as `ARCHIVED` (move to `docs/_archive/`) so a new agent isn't
  confused by 5 overlapping HANDOVER files.

### Step 5 — Record the audit + this plan
- Save this audit + plan as `docs/AUDIT_2026-08-12.md` (or `docs/AUDIT.md`), cross-linked from the
  companion so the next agent knows the state and the plan.

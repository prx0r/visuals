# Recipe — Resolve an uncertain title

You have a catalogue title, a manuscript label, or a misspelling and you don't know which Pāṭala work it is. Use the resolver. It returns **ranked candidate identities** — never a confident assertion.

## POST /api/resolve/work

```bash
curl -X POST "http://localhost:3000/api/resolve/work" \
  -H "Content-Type: application/json" \
  -d '{"title": "Amṛteśatantram"}'
```

Response:

```json
{
  "status": "machine_proposed",
  "count": 1,
  "candidates": [
    { "work_id": "netratantra", "title": "Netratantra / Amṛteśatantra", "urn": "tantra:text:netratantra", "confidence": 0.8, "evidence": ["title match (1.00)"] }
  ]
}
```

**What `status: "machine_proposed"` means:** the identity is a *candidate*, generated by a machine, and is **not** accepted scholarly knowledge. Only a human review event can promote a candidate to an accepted work identity. Pāṭala distinguishes *proposing* an identity from *asserting* it.

## Input fields (all optional, but give at least one)

| Field | Example |
|---|---|
| `title` | `"Kubjikamatatantra"` |
| `incipit` | the opening words, to match manuscript incipits |
| `alternateTitles` | `["Kubjikā Tantra"]` |

## Gold cases (what you should be able to assert)

```bash
curl -X POST http://localhost:3000/api/resolve/work -H "Content-Type: application/json" -d '{"title":"Kubjikamatatantra"}'
# → kubjikamata is a candidate

curl -X POST http://localhost:3000/api/resolve/work -H "Content-Type: application/json" -d '{"title":"zzzqqqxxxnomatch"}'
# → no confident resolution (low/empty candidates)

curl -X POST http://localhost:3000/api/resolve/work -H "Content-Type: application/json" -d '{"title":"Amṛteśatantram"}'
# → netratantra is a candidate (its alias)
```

**Invariant:** the resolver can **never** return an `accepted` status. If you see `machine_proposed`, treat it as a hypothesis to verify against the work's bibliography (`/api/texts/{id}`) and manuscripts (`/api/works/{id}/manuscripts`).

---

**MCP:** `get_work({ id })` after you've identified the id. The resolver itself is API-only for now.

# Concepts — the epistemic model

Everything Pāṭala serves is an instance of one of these layers. Understanding them is the whole API.

```
SOURCE      what upstream material says
PROPOSAL    what a machine/human suggests (never auto-accepted)
ASSERTION   a structured, reviewable claim
REVIEW      a recorded judgment (who / what / decision / why / when)
ACCEPTED    Pāṭala's current editorial position
```

## The rules

```
Proposal ≠ assertion.
Assertion ≠ consensus.
Accepted ≠ certain.
Machine score ≠ scholarly confidence.
```

## What each status means

### `machine_proposed`
Generated by an automated process (the resolver, an LLM, a detector). It is a **hypothesis**, not accepted knowledge. It must never be reported as fact.

### `verified: false` (bibliography seed records)
Metadata has the full production schema but has **not yet received the project's gold audit**. It's not wrong; it's *not yet audited*. `verified: true` (the Trika-10) has been gold-audited.

### `accepted` (term senses)
Current Pāṭala editorial state. It is the review-promoted position — **not** universal, uncontested scholarship.

### `expert_reviewed` (assertions)
Reviewed by a contributor whose review event and scope are recorded. The review event is stored (who/what/decision/why/when), not just a `reviewed: true` boolean.

### `partial` / `none` translation status
The deliberate phrasing is **"No complete English translation located"** — never "Untranslated." It means Pāṭala searched and did not locate one, as of `statusChecked`. New editions can supersede it.

## Why this matters

It makes Pāṭala safe for AI. An agent can tell a *proposal* from an *assertion*, a *draft translation* from a *reviewed one*, a *verified* record from an *un-audited* seed — and cite accordingly. That is the difference between a corpus and an *evidence graph*.

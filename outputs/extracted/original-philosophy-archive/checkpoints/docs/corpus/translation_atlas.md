# Translation Atlas — Period-Organized Corpus Plan (Tantra + Nyāya)

*Strategy: translate by period-cluster, not text-by-text. Texts of one period share one lexicon (and often one authorial circle), so every verse translated enriches the next. Each cluster gets a shared period-glossary as it is worked.*

*Assets legend: **[ZIP]** = in the downloaded Muktabodha e-text library (499 texts) · **[DISK]** = already on disk (GRETIL/corpus/Dyczkowski) · **[DONE]** = translated already · **[ACQUIRE]** = not on disk yet*

# PERIOD-GLOSSARY RULE

Start one `period-glossary-<cluster>.md` per cluster before translating it. Seed from the risk-terms already established (nirañjana, yoni, śabdabrahman, vimarśa, prakāśa, sambandha, samayācāra, vidyā...). Each entry: term → renderings used per text → context-dependence notes → parallel citations. The glossary grows from each translation and feeds the next — that is the compounding-context engine.

# LEAPFROG EXPANSION MAP (2026-08-09)

*Rule: each hop starts from (a) a text we have translated ourselves, and (b) a published English translation we hold as verification reference. The next text must share the specialist literature, adding new vocabulary while the reference-anchored glosses carry over. Unanchored texts wait until anchored hops have built the period-glossary.*

# THE TRANSLATION + COMMENTARY EVOLUTION (2026-08-09) — strategy note

**The three-readings format is designed to evolve, pass by pass, into a full translation + commentary apparatus.** Part 2 (the doctrinal/contextual reading) becomes the seed of the commentary layer:

- **Pass 1** = working translations (done for the complete texts)
- **Pass 2** = verification + correction (in audit docs, never silent edits) + **commentary stubs** — brief interpretive notes in Part 2 with ideas, flagged as stubs (not yet full commentary)
- **Pass 3+** = the stubs grow into full commentary (the Dyczkowski model: translation → commentary-translation → exposition → notes), each pass deepening the stubs while the audit trail grows
- The **period-glossary** is the commentary's lexicon; the **cross-text network** is the commentary's evidence base

**Why this works:** we have the full time-period and author context hot right now (the Kaula corpus, the Trika stack, the anchors). Commentary written now would be informed by the whole batch; commentary written later, cold, would be thinner. The stubs capture the ideas now at low cost; the deepening happens naturally as more texts come in.

**The Dyczkowski model (from his intros on disk — studied 2026-08-09):**
1. Sūtra-list first (his renderings, parenthetical insertions marked)
2. Author-biography first (lineage, gotra, migration-history, teacher-chains — cf. his Rājānaka Rāma biography)
3. Per-sūtra: translation → commentary-translation → **his own Exposition** (the comparison of commentaries as the interpretive engine)
4. Numbered endnotes (textual variants, parallel-text quotations)
5. The myth-of-origin framing (the revelation narrative as entry-point)
6. The method-statement (dedication/acknowledgments = intellectual provenance)

**Commentary-stub conventions (for pass 2 docs):**
- `[STUB: ...]` — an interpretive idea, flagged as a stub, to be deepened in pass 3+
- Stubs are written in Part 2 of the three-readings files (the doctrinal reading) or in the pass-2 docs
- A stub must anchor to at least one piece of evidence (a parallel text, an anchor-passage, a period-context fact)

# THE THREE-VERSION FLOW (2026-08-09) — supersedes the single-translation model

Full spec: `corpus/targets/translation_flow_spec.md`. **T1 → R1 → T2 → R2 → T3-FINAL.**

- **T1** = the pass-1 files (15 works, done) · **R1** = the P2 peer-review docs (15 works, done)
- **T2** = a fresh translation, composed blind of T1's sentences, with a declared different strategy (commentary-informed / argument-priority / anchor-influenced / register-shifted); passage-level re-composition required, word-level reuse allowed
- **R2** = the T1-vs-T2 per-verse comparison: hard-core (independent agreement), divergence, adjudication with [G]/[P]/[A] evidence or OPEN — the commentary grows here; converges near-final
- **T3** = the final synthesis — the only artifact allowed the word "complete"

Per-text status lines: `T1-done → R1-done → T2-done → R2-done → T3-FINAL`. The flow IS the error-measurement (hard-core/OPEN rates published per text); the anti-cheat structure counters the self-review bias; the anchors are the referee in R2.
